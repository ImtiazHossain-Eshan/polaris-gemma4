# Polaris demo recording checklist (2-3 minutes)

## Before recording

- Confirm the deployed `/demo` loads in a private browser window.
- Confirm the badge says **Live Gemma 4 prototype**.
- Generate once and verify the trace says `gemma-4-26b-a4b-it` and **Generated by Gemma 4**.
- Close personal tabs, notifications, terminals with secrets, and browser extensions.
- Record at 1080p with browser zoom around 90-100%.
- Keep this script on a second device if possible.

## Recording flow

### 0:00-0:15 - Set the stakes

Show the hero and say:

> Students do not need another page of generic admissions advice. They need to know what matters for their profile and what to do next. Polaris turns a small student snapshot into an evidence-grounded roadmap with Gemma 4.

### 0:15-0:35 - Explain the input

Scroll through the prefilled form.

> This is a realistic Bangladesh profile: late high school, targeting a global top-50 bachelor's program, a 3.72 GPA, and community experience but no research signal.

Toggle **Research** on and off once so personalization is visible, then leave it off.

### 0:35-1:10 - Generate

Click **Generate my roadmap**.

While it runs:

> Polaris validates the profile, uses deterministic BM25 to retrieve relevant university and scholarship evidence, then gives that grounded context to Gemma 4 through a compact diagnosis and parallel one-milestone schema stages.

Do not cut away from the loading state unless latency exceeds 20 seconds.

### 1:10-1:55 - Prove the result

Point to these areas in order:

1. exact Gemma 4 model ID and thinking level;
2. strategic summary;
3. honest gaps;
4. retrieved evidence chips;
5. one milestone's action and success metric.

Say:

> The result is not free-form text. Every milestone is typed product data with a time window, category, priority, rationale, and measurable outcome. That means the full workspace can track and adapt it over time.

### 1:55-2:25 - Show technical integrity

Open the GitHub repository to `lib/llm/gemma.ts`, then `lib/llm/providers/registry.ts`.

> Gemma 4 is the only generative model. The server allowlists the official 26B and 31B model IDs, the provider registry contains one adapter, and client preferences cannot bypass that policy. Retrieval and probability scoring are deterministic supporting algorithms.

### 2:25-2:45 - Close on impact

Return to the roadmap.

> Polaris makes strategic guidance more accessible to students who cannot rely on a private counselor. It turns open-model capability into a plan a student can begin this week.

End with the live URL visible for two seconds.

## Required evidence to capture

- Public URL with no authentication prompt
- Input form interaction
- Loading/generation state
- Gemma 4 trace
- At least three roadmap cards
- Retrieved evidence
- GitHub single-model boundary
