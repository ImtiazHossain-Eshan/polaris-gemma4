# Polaris demo recording checklist (2-3 minutes)

## Before recording

- Open the deployed `/demo` in a private browser window.
- Confirm the left rail says **All access** and the page does not request a login or payment.
- Open **New setup / replan**, generate once, and verify the trace shows a Gemma 4 model ID.
- Test one Strategist prompt and confirm retrieved source chips appear.
- Close personal tabs, notifications, terminals with secrets, and browser extensions.
- Record at 1080p with browser zoom around 90%.

## Recording flow

### 0:00-0:18 - Set the stakes

Show the full roadmap workspace and say:

> Students do not need another page of generic admissions advice. They need to know what matters for their profile and what to do next. Polaris turns a Bangladeshi student's ambition into an evidence-grounded plan with Gemma 4.

Point out the complete starter roadmap, progress ring, honest gaps, and evidence panel. The product is useful before the first click.

### 0:18-0:48 - Prove the model is central

Open **New setup / replan**, briefly show the realistic Class 11-12 profile, then click **Generate with Gemma 4**.

While it runs, say:

> Polaris validates the profile, ranks curated university, scholarship, and case-study evidence with deterministic BM25, and gives that context to Gemma 4. Gemma 4 performs the strategic diagnosis and returns schema-constrained milestones with dates, priorities, rationales, and success metrics.

### 0:48-1:18 - Prove the result works as a product

Show the generation trace, open one roadmap mission, and mark it complete.

> This is operational product data, not a chat transcript. Each mission can be tracked, inspected, and used as context for future decisions. If the hosted model is temporarily unavailable, Polaris visibly labels a deterministic fallback instead of pretending another model produced the answer.

### 1:18-1:48 - Ask the grounded Strategist

Use the right rail prompt **What is the highest-leverage thing this week?**

> The Strategist can see the current roadmap and active workspace section. Its answer is generated by Gemma 4 and grounded in retrieved evidence, so the student gets a decision and next action rather than generic motivation.

Point to the model trace and source chips below the reply.

### 1:48-2:20 - Show breadth without friction

Move quickly through the left navigation:

1. **Universities** - adjust one scenario-lab input and show fit bands or comparison.
2. **Resources** - show admit stories, scholarships, costs, exams, and guides.
3. **Deadlines** - complete a deadline or add one.
4. **Partners** or **Consultants** - show matched, interactive cards.
5. **Community**, **Family**, **Bookings**, and **Settings** - point out that every surface is available without an account or checkout.

Say:

> The judge workspace is isolated from real accounts but it is not a static mockup. The fit engine, resource data, matching logic, local interactions, and Gemma 4 endpoints all run. Every original user-facing area is discoverable from one route.

### 2:20-2:42 - Show technical integrity

Open the repository to `lib/llm/gemma.ts`, then `lib/llm/providers/registry.ts`.

> The server allowlists only Gemma 4 model IDs, and the provider registry contains one generative adapter. Retrieval, probability scoring, validation, and the availability fallback are deterministic supporting components.

### 2:42-3:00 - Close on impact

Return to the roadmap and say:

> Polaris makes strategic guidance more accessible to students who cannot rely on a private counselor. It turns open-model capability into an evidence-backed plan a student can begin this week.

End with the public URL visible.

## Required evidence to capture

- Private-window access with no authentication or payment
- Full workspace navigation and complete starter roadmap
- Live Gemma 4 roadmap generation
- Model trace and retrieved evidence
- One tracked mission and one interactive non-AI feature
- Grounded Strategist response
- Repository single-model boundary
